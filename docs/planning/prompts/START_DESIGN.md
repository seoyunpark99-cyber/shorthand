# START_DESIGN — SHORTHAND MVP 디자인 세션 시작 프롬프트

아래 블록을 새 대화의 첫 메시지로 붙여 넣고 `DESIGN_HANDOFF.zip`을 첨부하세요. 받는 세션에는 **SVG 파일 작성과 PNG 래스터화(코드 실행 또는 벡터 도구), 이미지 생성 서비스(gpt-image-2.5) 접근, 효과음 생성 서비스(ElevenLabs Starter 이상) 접근**이 필요합니다. 없는 능력이 있으면 해당 에셋만 보류하고 시작 시 알려야 합니다.

---

첨부한 디자인 인계 패키지 `DESIGN_HANDOFF.zip`을 읽고 지정된 에셋을 제작·정리하라. 게임 **SHORTHAND MVP (project_id: shorthand, contract_version 1.0)** 의 개발은 별도 세션이 기본 에셋으로 진행한다. 너의 범위는 시각·음향 제작과 규격에 맞는 납품이며 게임 로직이나 엔진 코드를 설계하지 않는다.

## 시작
1. `START_HERE.md` → `DESIGN_SPEC.md`(1~3절 전부, 이후 해당 유형 절) → `shared/asset_contract.json`·`shared/ui_tokens.json` → `briefs/pilot/*` → `JOBS_TRACE.md` 1절 순서로 읽어라. `shared/CONTRACT_HASH.txt`의 해시가 계약 파일과 일치하는지 확인하라.
2. 디자인 스택 결정(DC-04, 조사일 2026-09-17): HUD·아이콘·타일·카드 패널·파일럿 몸체 = 코딩 에이전트가 SVG 작성(vector_authored) / 기준 그림 = gpt-image-2.5(raster_generated) / 효과음 = ElevenLabs Starter 이상(audio_generated) / 글꼴 = 라이선스 자산(library_sourced). 각 브리프의 production_method에 필요한 도구가 실제로 준비되어 있는지 확인하라. 조사일로부터 3개월이 지났으면 gpt-image의 투명 배경 지원과 ElevenLabs의 상업 이용 조건을 다시 확인하고 달라진 점을 보고하라. 도구가 없는 에셋은 다른 방식으로 바꿔 만들지 말고 보류한 뒤 기획 세션에 방식 변경을 요청하라.
3. **승인된 기준 그림은 아직 없다.** 첫 작업 `job.pilot.ref_shot`이 기준 그림 후보 2~3안을 만드는 일이며, 사용자가 승인한다. 승인 전까지는 `DESIGN_SPEC.md` 2절의 아트 바이블과 공통 스타일 문단이 유일한 기준이다. 임의로 다른 참조를 승인 기준으로 삼지 마라.
4. 읽지 못한 참조는 추정하지 마라. 완료된 동일 버전 작업은 반복하지 마라.

## 진행 단계: 파일럿 먼저
이 인계는 1단계(파일럿)다. 파일럿 세트 `pilot.hud_combat`의 다음 작업만 제작하라: job.pilot.ref_shot(ref.shot.hud) → job.pilot.player_body → job.pilot.grunt_body → job.pilot.tiles(batch.tiles.yard) → job.pilot.shard → job.pilot.icons(batch.icons.main 17종) → job.pilot.card_panel → job.pilot.fonts → job.pilot.audio(3큐). 기준 그림 승인 후 몸체 작업을 시작하는 것이 순서이지만, 벡터 작업은 좌표 지시가 완결되어 있으므로 승인을 기다리는 동안 타일·아이콘·카드 패널·글꼴·오디오를 먼저 진행해도 된다.

납품할 것: 원본(SVG·생성 PNG·WAV), 규격에 맞춘 납품 파일, `DELIVERY_MANIFEST` 양식을 채운 `delivery/manifest.json`, 실제 크기 프리뷰(56px·20px 등 브리프가 요구한 것), 사용한 도구·모델 이름과 버전, 실제로 쓴 만드는 지시(수정했다면 수정본), 규격 검사와 각 브리프의 고유 검수 기준 결과, 제작 중 발견한 문제(지시대로 안 나온 부분, 시도 횟수, 도구 한계), 그리고 `FROM_DESIGN.md`.

**파일럿 납품 후 멈춰라.** 나머지 에셋(`briefs/phase3/`)은 기획 세션의 판정과 이어가기 인계를 받은 뒤 만든다. 판정에서 지시문이나 규격이 바뀌면 먼저 만든 에셋을 다시 만들어야 하기 때문이다.

## 제작
- 각 브리프의 '만드는 지시' 칸을 제작 도구에 넘기고, '규격 맞추는 지시' 칸으로 결과를 정리하라. 생성 서비스에 좌표·해시·파일 경로·job_id를 넣지 마라(생성 도구는 이 값을 지키지 못하고 그림에 숫자를 그려 넣기도 한다).
- 벡터 에셋은 브리프의 좌표·색값을 그대로 쓰고, 112×112(보스 160×160, 아이콘 64×64, 카드 240×320) PNG로 출력한 뒤 피벗·안전영역을 스크립트로 검사하라. 트리밍·회전 금지(피벗이 어긋난다).
- batch_id가 있는 에셋(batch.tiles.yard, batch.icons.main)은 묶음 브리프의 지시로 한 번에 만들고 규격 칸의 순서대로 잘라 각 ID에 매핑하라. 묶음 중 일부만 불합격이면 그 에셋만 다시 만들어라.
- asset_id, clip_id, frame_id(f0001, f0002), cue_id를 보존하라. 캔버스·피벗·프레임 수·duration·9-slice inset·오디오 규격을 임의로 바꾸지 마라. 더 좋은 표현에 계약 변경이 필요하면 영향 ID와 변경 요청을 남기고 독립된 작업은 계속하라.
- 공통 스타일 문단(DESIGN_SPEC 2절)은 글자 하나 바꾸지 않고 복사해 쓴다. 문장이 조금만 달라도 화풍이 흔들린다.

## 검수와 납품
- 규격 검사(캔버스·알파·피벗·안전영역·길이·피크·샘플레이트)와 스타일·청각 검토를 구분해 기록하라. 각 브리프의 고유 검수 기준을 실제 표시 크기에서 확인하라. 수행하지 못한 검사는 미실행으로 남겨라. 듣지 않고 청각 합격으로 표시하지 마라.
- 원본→후처리→납품의 대응을 기록하라(SVG→PNG 출력 설정, 생성 PNG→축소 프리뷰, MP3/WAV→WAV 48k→OGG).
- 반환 ZIP을 새 폴더에 풀어 필수 파일·원본·manifest·프리뷰가 있는지 확인하라. 파일 경로는 납품 루트 기준 상대 경로, 해시는 실제 sha256(계산 못 하면 비워 두고 표시).
- 기술 규격 충족, 사용자의 스타일 승인, 게임 통합 합격은 별개다. 엔진에서 확인하지 않았다면 통합 합격으로 표시하지 마라.
- 납품 정규화·검사용 스크립트는 만들어도 되지만 게임 코드나 엔진 프로젝트는 수정하지 마라. 지정 작업의 납품과 검수 기록을 반환하면 종료하며 통합·기능 개발·외부 공개는 별도 착수 권한을 따른다.

## 인계 문서 피드백 (납품물과 별도)
파일럿 납품과 최종 납품 때, 납품물과 **별도 파일** `FROM_DESIGN.md`로 인계 문서 자체에 대한 피드백을 돌려줘라. 기획 세션이 브리프 양식과 계약 문서를 고치는 데 쓰며 에셋 판정에는 쓰지 않는다. 적을 것: '만드는 지시'를 도구에 넣었을 때 지시대로 나오지 않은 부분과 시도 횟수, 실제로 통한 수정 지시 / '규격 맞추는 지시'에서 빠졌거나 모호했던 값 / 공통 스타일 문단이 유형별로 맞지 않았던 곳 / 도구 한계로 계약을 지킬 수 없었던 규칙 / 특히 잘 작동해서 그대로 두었으면 하는 지시. 각 항목에 근거(브리프 id·절·에셋 id)를 붙여라. 계약 변경 요청은 여기가 아니라 변경 요청 절차로 보내라.
