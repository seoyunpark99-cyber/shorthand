# INTEGRATE — 최종 통합 지시 (초안, 4단계용)

**이 문서는 초안이다.** 파일럿 판정(2단계) 후 계약 버전이 바뀔 수 있으므로, 기획 세션이 3단계 인계와 함께 최종본을 다시 발행한다. 그 전에는 사용하지 않는다. 받는 세션에는 코드 실행과 게임 빌드 실행 능력이 필요하다.

---

개발 세션의 최종 반환물과 디자인 세션의 최종 납품을 공통 에셋 계약(project_id shorthand, contract_version [최종본에서 채움], contract_hash [최종본에서 채움])에 따라 결합하라. 게임 로직은 승인된 상태를 유지하고, 개발이 준비한 `npm run assets:import` 검사·임포트·바인딩 교체 경로를 사용하라.

먼저 개발 기준 project_id·contract_version·hash와 디자인 delivery_id·contract_version·hash를 비교하라. 승인된 호환 관계가 없으면 불일치 납품을 적용하지 마라. 파일럿 때 이미 교체한 에셋(ref.shot 제외)도 최종 계약 버전 기준으로 다시 검사하라.

검사: ID·variant·clip/frame·의존성, 파일 존재·sha256·형식, 캔버스(112/160/64/240×320)·피벗·알파, 프레임 순서·duration(idle 450×2), 9-slice inset 24, 오디오 길이·48k→OGG·피크, 글꼴 라이선스 파일. 파일명이나 겉모습으로 매핑을 추정하지 마라. 계약에서 허용하지 않은 변환을 추가해 불일치를 숨기지 마라.

교체 단위(asset / batch / cue / font)별로 임시 준비 후 mapping에 적용하라. 프레임이 빠진 클립은 기본 에셋을 유지하고 사유를 기록하라. 적용 전후 manifest와 복귀 방법을 남겨라.

대표 장면(fixture pilot_hud, 레벨업 화면, 결과 화면)에서 실제 크기·위치·모션·UI 상태·오디오를 확인하고, 교체 전후 T-SIM-01(재현성)·T-E2E-01(전체 여정) 회귀를 수행하라. 게임 판정·저장·입력 결과는 계약상 동일해야 한다. UI는 8화면 각각에서 최종 토큰·파일이 실제 컴포넌트에 연결되는지 캡처와 입력 증거로 확인하라. 임포트됐으나 미사용인 파일, 미연결 슬롯, placeholder 잔여를 보고하라.

미등록 키·미납품·미승인·검사 실패와 기본 에셋 잔여 목록을 보고하라. 최종 파일로 연결됐다는 이유만으로 스타일 승인이나 출시 합격을 선언하지 마라. 에셋 교체를 위해 게임 규칙이나 계약을 바꿔야 한다면 영향 ID·원인·수정 책임·대안을 보고하라.

통합 결과와 **별도 파일** `FROM_INTEGRATION.md`로 인계 문서에 대한 피드백을 돌려줘라: 계약이나 manifest 규격 때문에 검사할 수 없었던 항목, 두 트랙 산출물이 어긋난 지점과 그 원인이 인계 문서 중 어디에 있었는지, 잘 작동한 지시. 통합 합격 판정과는 무관하다.
